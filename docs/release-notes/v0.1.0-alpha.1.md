# Resonance v0.1.0-alpha.1

`v0.1.0-alpha.1` is a source-only public alpha for developers and contributors evaluating Resonance. It contains no signed application, TestFlight build, hosted service, or production deployment.

Publication status: these are versioned candidate notes until the tag points to the merged `main` commit and GitHub marks the release as a pre-release. Verification results are finalized here only after the final candidate passes.

## Audience

This pre-release is for source review, local development, security and privacy evaluation, and contribution. It is not an end-user distribution.

## Capabilities

- Offline-first SwiftUI/SwiftData foundations for practice entries, media, calendar data, feedback, and queued work.
- Student and teacher course roles with private submission, review, and timestamped feedback flows.
- Audio evidence and consented teaching-lesson video with capture profiles and student-authored markers.
- Account-owner isolation, explicit local-profile replacement, protected files, and durable retry behavior.
- Fastify API with Prisma/PostgreSQL, S3-compatible object storage, loopback-only development auth, and configurable OIDC.
- Authorized short-lived media access for the owning student or a same-course teacher.
- Durable object-deletion jobs, bounded dependency operations, token-rotation replay containment, and destructive-database safety guards.
- Deterministic demo fixtures, service E2E, database regression tests, iOS XCTest, and local CI parity tooling.

## Known limitations

- The interface shown in this alpha is English; complete German localization and locale-specific review remain open.
- Capture editing and some preview, retake, history, Calendar, Export, Settings, Sync, permission, and recovery states need further work.
- The complete Dynamic Type, assistive-technology, keyboard, device-window, performance, and poor-network matrices have not been run.
- Real OIDC, production databases and storage, TLS, backups, retention, monitoring, signing, TestFlight, and deployment are not proven.
- Screenshots are deterministic visual evidence only and do not prove interaction, networking, authorization, persistence, or accessibility.

## Verification

The assembled release candidate passed the complete local gate twice on 2026-07-15:

```bash

```

Measured results:

- fixture validation, Docker Compose validation, secret scan, publication boundary, ShellCheck, and Actionlint passed;
- the public-doc validator resolved 21 Markdown files and 16 image references and verified one manifest with 12 unique approved captures;
- server formatting, lint, TypeScript build, Prisma generation, seven migrations, and the runtime readiness probe passed;
- the production dependency audit (`npm audit --audit-level=high --omit=dev`) reported zero vulnerabilities;
- 483 server tests across 36 files passed;
- coverage passed at 85% statements, 82.04% branches, 94.11% functions, and 85.39% lines;
- the process-level service E2E passed;
- iOS XCTest passed with Xcode 26.3 on an iPhone Simulator.

The all-dependency `npm ci` summary separately reports five development-tool findings (three moderate and two high). They are not present in the production-only audit and remain dependency-maintenance work; no forced major-version upgrade is included in this alpha.

Final GitHub Actions and CodeQL results are tracked on [draft PR #51](https://github.com/sebastianspicker/resonance/pull/51) and remain required before merge or publication.

The former Prisma `P2010` advisory-lock failure has focused database regression coverage. The implementation keeps transaction-scoped `pg_advisory_xact_lock` while returning a Prisma-deserializable scalar.

## Security and privacy

- Development auth must remain explicitly enabled and loopback-only.
- Teaching-lesson video remains local until submission begins and requires private-course-review consent.
- Private media URLs are authorized, short-lived, excluded from logs, and returned with `Cache-Control: no-store`.
- Account changes require explicit deletion of the existing local profile and pending work.
- No analytics, real identities, private recordings, credentials, or capture logs are included.

Report vulnerabilities through [GitHub private vulnerability reporting](https://github.com/sebastianspicker/resonance/security/advisories/new), not a public issue. See the [security model](../SECURITY.md).

## Local setup

```bash
cp server/.env.example server/.env
docker compose -f infra/docker-compose.yml up -d
cd server
npm ci
npm run prisma:generate
npm run prisma:migrate
npm run prisma:seed
npm run dev
```

Open `ios/ResonanceApp/ResonanceApp.xcodeproj` and run the shared `ResonanceApp` scheme on an iOS 17-or-newer Simulator. For deterministic mock data, use `./scripts/demo/bootstrap-local-demo.sh` and the [local demo runbook](../LOCAL_DEMO.md).

## Migration expectations

- The `20260715110000` migration revokes refresh tokens created by older source versions because those rows do not have reliable rotation-lineage identifiers; users must sign in again after upgrading.
- Five historical SQL migration files were formatting-normalized without changing the resulting PostgreSQL schema. Databases that recorded their earlier checksums must be rebuilt and replayed from the tracked migration chain. Do not edit Prisma's `_prisma_migrations` table.
- Back up any non-demo data and validate the complete migration chain in an isolated environment before considering deployment.
