# Resonance v0.1.0-alpha.1

`v0.1.0-alpha.1` is an unpublished source-only public-alpha candidate for
developers and contributors evaluating Resonance. It contains no signed
application, TestFlight build, hosted service, or production deployment.

Publication status: the tag and GitHub pre-release do not exist.

## Audience

This alpha is for source review, local development, security and privacy
evaluation, and contribution. It is not an end-user distribution.

## Capabilities

- Offline-first SwiftUI and SwiftData foundations for practice entries,
  protected media, calendar data, feedback, and queued work.
- Student and teacher course roles with private submission, review, authorized
  playback, and timestamped feedback.
- Audio evidence and consented teaching-lesson video with capture profiles and
  student-authored markers.
- Account-owner isolation, explicit local-profile replacement, protected files,
  and durable retry behavior.
- Fastify API with PostgreSQL, v1 sequential command synchronization,
  optimistic versions, idempotent receipts, S3-compatible artifact sessions,
  loopback-only development auth, and configurable OIDC.
- Race-safe artifact completion with immutable final keys, signer-derived
  credential expiry, bounded quotas, retention, and durable cleanup.
- Deterministic demo fixtures, server and iOS tests, strict static analysis,
  public-document validation, and a 12-scenario screenshot capture harness.

## Known limitations

- The interface is English. Complete German localization and locale-specific
  review remain open.
- Capture editing and some preview, retake, history, Calendar, Export, Settings,
  Sync, permission, and recovery states need further product work.
- The complete Dynamic Type, assistive-technology, keyboard, device-window,
  performance, and poor-network matrices have not been run.
- Real OIDC, production PostgreSQL and object storage, TLS, backups, retention
  operations, monitoring, signing, TestFlight, and deployment are not proven.
- Screenshots are deterministic visual evidence only. They do not prove
  interaction, networking, authorization, persistence, accessibility,
  localization, signing, or deployment.
- No screenshot set is currently approved for publication. A source-freeze
  recapture and visual review remain required.

## Verification status

The current working tree is not final release evidence. The source-freeze
commit must pass the complete local gate, backend coverage, process E2E,
SwiftLint 0.63.2, iOS XCTest with both compiler paths, documentation checks,
secret scan, and repository boundary checks.

GitHub Actions, CodeQL, branch protection, scheduled security checks, the
logged-out release page, signing, and source-freeze screenshots require
separate verification. See the
[release checklist](../RELEASE_CHECKLIST.md).

## Security and privacy

- Development auth is explicitly enabled and loopback-only.
- Teaching-lesson video remains local until submission begins and requires
  private-course-review consent.
- Private media URLs are authorized, short-lived, excluded from logs, and
  returned with `Cache-Control: no-store`.
- Account changes cancel active work and require explicit handling of the
  existing local profile.
- No analytics, real identities, private recordings, credentials, raw capture
  logs, or environment-specific secret files are included. The tracked example
  environment template still requires the manual review listed above.

Report vulnerabilities through
[GitHub private vulnerability reporting](https://github.com/sebastianspicker/resonance/security/advisories/new),
not a public issue. See [SECURITY.md](../../SECURITY.md).

## Version and setup

- Git/GitHub release identity: `v0.1.0-alpha.1`
- Server package: `0.1.0-alpha.1`, private
- iOS marketing/build version: `0.1.0` (`1`)

Apple marketing versions are numeric; the Git tag and release notes carry the
alpha suffix.

```bash
cp server/.env.example server/.env
docker compose -f infra/docker-compose.yml up -d
cd server
npm ci
npm run prisma:generate
npm run prisma:migrate
npm run prisma:seed
npm run dev
```

Configure the local environment copy with `AUTH_MODE=dev` and verify all
required values before starting the server.

Open `ios/ResonanceApp/ResonanceApp.xcodeproj` and run the shared
`ResonanceApp` scheme on an iOS 17-or-newer Simulator. See
[LOCAL_DEMO.md](../LOCAL_DEMO.md) for deterministic mock data.

## Migration expectations

- The alpha uses one squashed baseline migration:
  `20260716000000_alpha_baseline`.
- Existing alpha databases must be backed up if needed, destructively rebuilt,
  and migrated from that baseline.
- Never edit Prisma's `_prisma_migrations` table.
- The app records the local alpha data version only after old local data
  surfaces are removed and their absence is verified. Ambiguous existing data
  is preserved for recovery rather than deleted.
- This is not a production migration path. Validate an isolated fresh database
  before considering deployment.
- Development mode defaults `HOST` to `127.0.0.1` and rejects explicit
  non-loopback hosts. Production mode requires an explicit `HOST` value.
- Server tests run without loading a local `.env` file; test harnesses must
  provide their environment explicitly.
