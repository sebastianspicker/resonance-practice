# Support

Resonance is a source-only public alpha for developers and contributors. It is
not an end-user service and does not provide a support SLA.

## Start here

- Setup or local verification: [README.md](README.md) and
  [docs/RUNBOOK.md](docs/RUNBOOK.md)
- Product, API, architecture, and evidence: [docs/INDEX.md](docs/INDEX.md)
- Known alpha limitations: [release notes](docs/release-notes/v0.1.0-alpha.1.md)

## Ask for help

- Reproducible defect: open an
  [alpha bug report](https://github.com/sebastianspicker/resonance/issues/new?template=bug_report.yml).
- Product proposal: open a
  [feature request](https://github.com/sebastianspicker/resonance/issues/new?template=feature_request.yml).
- Documentation problem: open a
  [documentation issue](https://github.com/sebastianspicker/resonance/issues/new?template=documentation.yml).
- Security vulnerability: use
  [private vulnerability reporting](https://github.com/sebastianspicker/resonance/security/advisories/new),
  never a public issue.

Include the source revision, affected surface, operating system/toolchain,
reproduction steps, expected behavior, and redacted diagnostics. Never attach
credentials, tokens, environment files, signed URLs, private recordings, or
real student data.

## Outside the alpha support boundary

The repository does not currently promise production hosting, live university
SSO integration, data migration for deployed systems, TestFlight distribution,
device signing, backup operations, or compatibility with real institutional
data. Those remain deployment and pilot-validation work.
